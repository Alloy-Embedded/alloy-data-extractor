# Add Coverage Index + Dashboard

## Why

Once Phase 2.1 (`add-bulk-discovery-cmsis-pack-manager`) and 2.2
(`add-cross-source-merge`) ship, alloy-devices-yml carries
thousands of YAMLs.  Today there is no machine-readable list of
which `(vendor, family, device)` triples exist, which sources
they were extracted from, or which extractor revision produced
them.  Reviewers cannot answer "what did this PR add?" without
diffing the whole tree.

This change adds `alloy-devices-yml/index.yml` — the catalog —
plus a CI dashboard that publishes coverage drift weekly.

## What Changes

- New file `alloy-devices-yml/index.yml`: every triple +
  provenance + schema_version + last-extracted-at.
- Generated by a new CLI: `alloy-data-extract index`.
  Walks `vendors/**/devices/*.yml` and rebuilds the index from
  the YAMLs themselves (no separate source of truth).
- A schema for `index.yml`: `schema/catalog/index.schema.json`.
- CI gate in alloy-devices-yml: any PR that adds/removes/renames
  a device YAML must update `index.yml`; if the index is stale
  the PR fails.
- A `coverage-dashboard.md` published weekly to alloy-devices-yml's
  GitHub Pages summarising:
  - Vendor × source matrix (chip count per cell)
  - Top 10 chips by extraction churn
  - Schema-version distribution
  - Source-pin freshness (days since each pin was bumped)

## Impact

- alloy-data-extractor: +~250 LOC (`index.py` + dashboard generator).
- alloy-devices-yml: +`index.yml` (~1 line per chip, MB-scale at 8000 chips).
- New schema: `index.schema.json`.

## What this does NOT do

- Does not extend coverage to new vendors.  Pure observability.
- Does not change `device.schema.json`.
